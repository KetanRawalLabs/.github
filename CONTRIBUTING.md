# Contributing

Thanks for helping improve a KetanRawalLabs project. Each repository may add project-specific steps; follow those first.

## Before opening an issue

Search existing issues and documentation. Include the repository, version, operating system or runtime, steps to reproduce, expected result, actual result, and relevant sanitized logs. Never post credentials, private data, or security vulnerabilities in a public issue.

## Changes

- Keep a change focused and explain the problem it solves.
- For code changes, update documentation and add or update checks when appropriate.
- Run the checks documented by that repository and report the results honestly.
- Keep commits understandable and avoid unrelated formatting changes.

## Pull requests

Describe the change, motivation, user-visible impact, and verification performed. Link related issues. Include screenshots for UI changes when useful. Call out behavior changes, migration steps, and known limitations. Maintainers may ask for revisions or close a change that does not fit the project’s scope.
